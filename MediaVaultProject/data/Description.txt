Project: MediaVault (CLI Library / Media Manager)
A command‑line app to manage a collection of media items (Books, Movies, Games).
You can add / list / search / sort / check-out / return / save / load items.
It covers:
✅ Program structure (multi-file)
✅ Variables/constants
✅ Arrays + vectors (std::array, std::vector)
✅ Statements/operators + program flow (menus, loops, switch)
✅ Characters/strings
✅ Functions
✅ Pointers/references (raw non-owning pointer + references)
✅ Classes/objects
✅ Operator overloading (Date, stream <<)
✅ Inheritance + polymorphism (abstract base class + virtual functions)
✅ Smart pointers (std::unique_ptr)

What the app does
You can:

Add Book / Movie / Game
List all items
Search by title keyword
Sort by title (asc/desc)
Checkout / Return items
Save/load to a CSV file

What the project does (exact behavior)
You build a command-line application that manages a collection of media items:
✅ Supported item types

Book
Movie
Game

All items share common fields:

id (unique number)
title (string)
addedDate (Date type)
status (Available / CheckedOut / Lost)

Each type adds its own extra fields:

Book → author, pages
Movie → director, minutes
Game → platform (PC/PlayStation/Xbox/Switch)


Main features (what user can do in the app)
1) Add items
User chooses item type → enters data → item gets stored in memory.
2) List all items
Print every item in the library in a nice human-readable format.
Example output:

[Book] #12 "Clean Code" by Robert Martin (464 pages) | Added: 2026-05-18 | Status: Available

3) Search by keyword (title)
User enters a word like "code"
You print all items whose title contains that keyword (case-insensitive).
4) Sort items by title (asc/desc)
User chooses ascending/descending
You sort the whole collection.
5) Checkout & Return

Checkout: changes status from Available → CheckedOut
Return: changes status from CheckedOut → Available
If invalid (e.g., checkout already checked out), you throw an exception.

6) Save & Load
When exiting, save items to a file (e.g. CSV):

On start, load existing file if available.

So your program “remembers” items between runs.
